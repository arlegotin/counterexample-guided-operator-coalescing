# Qualified local compute assumptions

Qualification date: 2026-10-27. Evidence: [compute-path summary](../provenance/qualification-2026-10-27.json) and [exact tested dependencies](../provenance/dependency-locks/README.md).

The WP00 **compute path** passed on native Apple M3 Max, macOS 26.7.1, CPython 3.12.9 arm64. The full WP00 gate remains `pending_asset_provenance`: immutable teacher/data revisions and terms have not been established. Actual teacher shapes/numerics, native model export and quantizer format gates remain future work. No checkpoint or dataset was downloaded.

Scientific execution uses PyTorch FP32 on the validated MPS path. CPU FP32 remains an explicitly labeled alternative; CPU FP64 supplies numerical references. MPS fallback is refused when `PYTORCH_ENABLE_MPS_FALLBACK=1`; no allocator limit is removed. MLX executes on its native GPU. Default tests exclude hardware markers; explicit MPS/MLX tests are separate evidence. Missing counters and unavailable operations retain null measurements and reasons. A restricted-process failure does not establish host incompatibility: authorized escalated sysctl, networking and Metal probes succeeded here.

The physical capacity is 36 GiB. At the recorded snapshot the `vm_stat` free + inactive + speculative estimate was 9,153,970,176 bytes, pressure-free percentage 45, used swap 22,287,944,253 bytes, and disk free 210,418,249,728 bytes. These quantities change with other applications. Reclaimable pages are an estimate, not reserved capacity. The doctor bounds initial fixture tensor allocations by `min(64 MiB, measured estimate / 4)` and requires at least 1 MiB; runtime initialization/driver memory is outside that tensor cap. No larger allocation or training budget follows from this snapshot.

Eight eager fixtures test causal attention, RMSNorm (epsilon 1e-5), SiLU, gather/patch, checkpoint recomputation, shared-parameter gradient accumulation, frozen suffix input gradients, and a tied-head/GQA/RoPE tiny decoder. Bounded deterministic arrays avoid PRNG-version variation. FP32 errors are compared with CPU FP64 using `64 × dtype epsilon × max(1, reference maximum absolute value)` separately for forward outputs and gradients. The factor bounds a tiny 64-term accumulation scale; recorded errors, exact repeat checks, independent gradient-sum/causality checks, and central FP64 finite differences accompany this screen. It is not a full-model tolerance. Task 3/7 must establish mathematical/model acceptance tolerances at representative shapes.

FP16/BF16 were measured separately. Their dtype-relative screening passes authorize no reduced-precision scientific run: observed BF16 errors reach 0.116 in outputs and 0.296 in gradients. FP32 remains binding. MLX lacks `ArrayAt.set` in the tested release; the equivalent eager `scatter_add(patch - gather(source))` passes forward/gradient comparisons. This is a local probe implementation, with no third-party patch. MPS float64 is unsupported by Metal; references explicitly transfer to CPU before converting dtype.

The measured tiny MPS forward/backward calibration averages three warmed calls on a 1×4-token, width-12 decoder, including fixture creation and checks. It is neither a 135M-model update cost nor a throughput forecast. Full-model update time, useful-scale memory peak, teacher/suffix/search costs, experiment ceilings and sample sizes remain unresolved until WP07. Primary context 512, temperature 1.0, head-position chunk 32, 8192 valid predicted targets/update, K=15/rank8/scale1, and the 4-bit/group64 BF16-residual anchor remain unchanged; tiny probes do not qualify that anchor.

Native Transformers and MLX-LM tiny Llama models ran offline with tied embeddings and GQA. A 64×64 4-bit/group64 MLX quantized matmul smoke test passed against dequantized weights; no bank bundle, actual teacher or quantized-refinement claim follows. Installed quantizer modules are `mlx_lm.quant.{gptq,awq,dwq,dynamic_quant}`; all four `--help` commands exit 0. GPTQ/AWQ/dynamic quantization bind `mlx_lm.quant.utils.load_data(tokenizer, num_samples, sequence_length)`. DWQ instead uses `mlx_lm.quant.dwq.load_data(tokenizer, data_path, num_samples, max_seq_length, num_valid_samples=32)` via tuner datasets. Future wrappers must replace these boundaries with manifest-controlled project data and test that default download paths cannot run; no quantizer calibration was invoked.
