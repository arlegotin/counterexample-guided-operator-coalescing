# Teacher and task scoring v1

`python -m poc validate --suite teacher_and_harness` executes the local WP02 qualification on MPS. Explicit `--device cpu` labels CPU execution; unavailable MPS fails without a fallback. `--config` defaults to `configs/135m.yaml`; `--out` names the private qualification artifact directory. Keep a separate output directory for every attempt. The existing WP01 component and public local preparation gates are prerequisites. No network or protected permit is used.

`AssetManifest.load(path, expected_sha256=...)`, `load_teacher(asset, config)` and `load_tokenizer(asset)` verify the manifest and every declared local source file before loading. Only safetensors, local files, a supported Llama configuration and `trust_remote_code=false` are allowed. Unverified sidecars are refused. The loader removes Transformers' injected local `_name_or_path` from executable identity. Raw checkpoint and tokenizer files remain unchanged.

`PromptPolicy` freezes the tokenizer identity, context, joint continuation boundary, BOS/EOS convention, scoring normalization, ties and reliability bins. ARC uses `Question: {question}\nAnswer:` followed by one space and the full answer. The complete concatenation is tokenized jointly. Offsets may not cross the boundary, and its prefix IDs must exactly match the separately encoded prefix. Unresolved boundaries and over-context inputs fail visibly. ARC has no appended answer EOS. Primary scores are mean answer-token log likelihood; raw sums and sum-score predictions are retained as secondary results. Exact ties choose the lowest original option index. Temperature-one softmax of mean scores supplies log loss, multiclass Brier sum and fixed ten-bin reliability rows.

BLiMP conditions on the first native token, inserts no BOS and appends one real EOS (ID 0). It scores all subsequent tokens including that EOS, using summed log probabilities. Exact ties earn half credit. Aggregate outputs retain every paradigm and distinguish macro accuracy from item-weighted accuracy. This convention is explicit because native SmolLM2 tokenization adds neither BOS nor EOS; it is a subset protocol, not an unspecified standard-harness reproduction.

Synthetic labels come from copying, dictionary lookup, bounded integer addition and finite functions. Development and confirmation use disjoint templates, operand ranges and composition order. The teacher is never trained for these tasks. The development screen freezes 16 cases per family, greedy decoding, a 32-token limit, first newline after nonwhitespace content or real EOS as termination, and exact string comparison after outer-whitespace stripping. Separate copy guards retain full labels at payload lengths 128/512/2048/8192, reserve all required output tokens, and reject inputs exceeding the declared context. Failed guards are reported separately from capability accuracy. A forward-only secondary context measurement does not certify long generation.

`score_arc`, `score_blimp` and `evaluate_synthetic` return frozen `TaskPrediction` rows with item/dependency identities, prompt hashes, scores/counts, labels, predictions, ties and visible failures. Scoring failures remain in the declared accuracy denominator. Failed rows have no calibration probabilities; `calibrated_items` reports that denominator explicitly. No failed or teacher-unsuccessful item is silently dropped.

`evaluate_documents(teacher, candidate, batches, negative_kl_floor=..., chunk_size=32)` yields `DocumentMetric` rows using `MetricSums`. It preserves raw finite negative KL and rejects a row below the measured backend/profile floor per valid target. `aggregate_documents` consumes those validated rows, rejects a zero-target population, sums in Python FP64 and divides by total valid targets. Real EOS depends on the target mask, never padding-ID equality. Independent windows reset model positions; source starts remain in their window identity.

The WP02 plan saves exact development IDs and policies before the first task prediction. Metadata is restricted to dev and then source/split before `open_records(..., purpose='selection')`. The reader durably records a unique per-read exposure intent ID before original-text I/O, then complete component fingerprints before yielding; interrupted repeat reads cannot reuse an earlier completion. Legacy intent/completion counts also fail closed during rebuilds. Selected natural/WikiText token files are verified only after exposure. The complete immutable window manifest is hashed without decoding protected token arrays; selected windows are reconstructed using the saved preparation seed/policy. Preserve the exposure ledger. Protected readers remain denied until Task 22.

Executable checkpoint identity includes the `eager-llama-hf-fp32-reciprocal-true-fp64-v2` profile. Scientific FP32 follows the installed original HF reciprocal-power RoPE operation order; the mathematical CPU FP64 norm/RoPE/softmax reference remains distinct. Tensor snapshots recheck versions, owners, storage pointers, shape/stride, configuration and dtype/device. Every executed input, post-attention and final RMSNorm epsilon is validated as positive and finite and bound into both snapshot and full identity; prior caches reject any epsilon change, including after explicit invalidation. Writers bypassing version counters through `.data`, external storage or NumPy must call `invalidate_state_snapshot()` before any digest/probe/cache use. Bank wrappers must match their declared partition and owner references before digest issuance.

See [measured teacher evidence](../provenance/teacher-qualification-2026-10-27.json) for the actual backend-specific numerical floors and finite workload results. They qualify this checkpoint and tested shapes, not arbitrary candidates, training memory or final study budgets. Teacher success, unknown pretraining contamination and small synthetic populations limit later preservation claims. No compression advantage has been demonstrated.
