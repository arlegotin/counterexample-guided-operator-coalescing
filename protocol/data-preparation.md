# Local data preparation contract v1

`python -m poc prepare --config configs/135m.yaml` verifies the public-source terms/revision gate and WP00 compute/WP01 component evidence, fetches only pinned safe public files, then produces outcome-blind metadata, original text, tokenizer IDs and windows under the ignored configured output directory. It neither loads teacher weights into a model nor evaluates answers, predicts tokens, trains, or issues confirmation permits. `configs/preparation-smoke-135m.yaml` describes the earlier immutable smoke population; the active configuration describes the fresh initial expansion and hashes its parent receipt.

`provenance/assets-135m-sources.json` contains full upstream commits, Git object IDs or upstream SHA-256 values, exact reviewed source-card/license snapshot hashes and source qualification. Small Git-tracked files are checked against their immutable Git blob identity before recording their actual SHA-256; LFS files are checked against upstream SHA-256. The FineWeb parent parquet SHA-256 is provenance, **not a claim of downloading or locally verifying the whole shard**. Each actual HTTP range has its offset, byte length, private path and SHA-256, and each retained record keeps the upstream shard/revision/row/ID and an original-text digest. Finite preparation ceilings are operational limits, not final study budgets. Every FineWeb request jointly preflights the range and global download ceilings before HTTP. A single-writer logical disk budget snapshots existing output paths (including reused hardlinks), reserves new file bytes before creation, and counts both partial/publish aliases until the partial is removed. Git/LFS/range retrieval also checks disk headroom before HTTP. Original text, token files, manifests, verification receipts and the encoded final preparation receipt all pass the disk guard. The final receipt is encoded once before its reservation; it does not include a self hash or recursively computed self size. Historical generation receipts remain attributed to their original code; later guard fixes and integrity-only checks are recorded separately.

The preparation receipt hashes the teacher asset manifest, all output manifests, private originals/token arrays, actual downloads and retained source ranges. A later invocation validates all recorded hashes and writes an independent verification receipt under `artifacts/preparation-verifications/`. Generation and verification receipts preserve code hashes, source commit/dirty patch digest, the complete configuration and dependency lock identity; they are preparation receipts, not experimental `RunSpec` method runs. Verified source files may be reused by immutable hardlinks; writers exclusively create files and never modify linked asset bytes in place.

For Task 7, verify the receipt and use `load_manifest(path, expected_sha256=..., roles={"dev"})` to obtain only the named role's metadata. Further select the needed source using metadata before passing a manifest to `open_records(manifest, purpose="selection")`. Gradient fitting/calibration accept only `fit`; counterexamples accept `fit`/`probe_fit`; ranking accepts only `probe_score`. All roles are checked before any text I/O. Text returned by the reader preserves original UTF-8 bytes, including CRLF. The reader records an append-only exposure snapshot of each accessed component before yielding text. Both checkpoint files and local data paths remain private and ignored.

`WindowRecord.target_indices` are **local token indices**, starting at 1 because token 0 has no preceding logit. To build `Batch.target_mask`, set entry `i - 1` for each target index `i`. `position_ids` always reset to `0..S-1`; `source_start` preserves the original document offset. Short sequences retain their available targets. Native SmolLM2 tokenization introduces neither BOS nor EOS; preparation explicitly appends one real EOS (ID 0) per independent sequence/benchmark sentence, with no BOS. Token files have a `fields` mapping: natural/WikiText `text`, ARC `question` and `choice_N`, BLiMP `sentence_good`/`sentence_bad`. No target can be inferred from padding ID equality.

Natural duplicate components use NFKC/casefold/whitespace normalization only for duplicate detection, identity/URL unions, seeded 5-word MinHash screening, exact Jaccard verification, and transitive closure. The three recorded thresholds are 0.7/0.8/0.9. Screening has approximate recall; exhaustive owned fixtures test the verified component logic. Cross-source benchmark overlap uses an exact inverted shingle index and quarantines whole natural components. This screen does not establish absence of partial-quote overlap, template similarity, or unknown teacher pretraining contamination.

Natural components receive salted 70/5/5/10/5/5 `fit/probe_fit/probe_score/dev/confirm_A/confirm_B` roles. ARC official test and WikiText official test are protected; other downloaded official splits are development. BLiMP fixes 100/1000 development pairs in every original paradigm using a salted ordering before scoring, protecting the other 900. The individual benchmark populations keep their official/paradigm identities. Cross-source checks do not relabel protected benchmark items.

`ExposureLedger.validate_rebuild` rejects prospective protected components overlapping any previous exploratory record/component identity or exact/near duplicate fingerprint, including new IDs and duplicate bridges. An exposure records every member of its supplied component, not only the selected document. Retain the ledger and all historical lineage; do not treat deletion or a new salt as resetting access. A preparation expansion with a parent manifest rejects any existing parent exposure and verifies its exact receipt before reassignment. Every fresh preparation additionally scans project exposure-ledger metadata and rejects after any historical exploratory exposure, including when a new directory omits a parent; integrity-only verification of existing immutable outputs remains available. The two initial preparation populations were fresh and outcome-blind, so their growth precedes exploratory exposure. Any later growth must preserve/check exposure lineage or fail closed. This is the conservative R10/R11 interpretation; no experiment-platform service is introduced.

All protected text readers currently fail closed. `EvaluationPermit` has no public constructor or issuer; Task 22 must add immutable freeze verification before enabling protected predictions. Direct filesystem access remains possible for the machine owner; these contracts guard accidental method leakage, not an adversarial owner.

The exact version/redistribution interpretation remains unresolved; local-only preparation and no raw redistribution are this project's scope, not a claimed research-only license restriction. FineWeb's ODC-By license covers database rights and does not clear every underlying web-text right. Retain attribution and source/terms references; no raw third-party data is committed.
