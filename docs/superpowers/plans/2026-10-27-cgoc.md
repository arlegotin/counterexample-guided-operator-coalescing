# Counterexample-Guided Operator Coalescing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a reproducible local experiment that determines whether candidate-specific counterexamples improve FFN sharing decisions and the complete quality/storage frontier, while accepting well-supported negative or inconclusive outcomes.

**Architecture:** One local Python harness supplies strict data access, decoder boundaries, canonical parameter ownership, cost accounting, evaluation, and statistical analysis to all methods. A diagnostic-first sequence gates the compiler and expensive comparator fitting; native deployment and protected confirmation are separate later stages. Every terminal gate can produce the final report without pretending later work ran.

**Tech Stack:** Native Python (3.11/3.12 starting candidates), PyTorch/MPS and CPU, Transformers/tokenizers, MLX/MLX-LM, safetensors, NumPy/SciPy/scikit-learn, datasets, PyYAML, pytest, process telemetry, and PyArrow for Parquet. Exact compatible versions and hashes are selected and locked in Task 2; no version here claims prior M3 validation.

**Spec:** [2026-10-27-cgoc-design.md](../specs/2026-10-27-cgoc-design.md). Read it with the [blueprint](../../blueprint.md) and [critical analysis](../../analysis/2026-10-27-blueprint-review.md).

**Status:** proposed implementation plan, not executed. Only documentation exists. All `poc`, `pytest`, model, and benchmark commands below describe future implementation/verification. Review the design and this plan before product implementation; the user has requested this documentation, not a completed experiment.

## Global Constraints

- Work on the current branch; do not create a worktree or switch branches for this project unless the user later requests it.
- Use one local Apple Silicon machine; no paid API, remote accelerator, or external teacher service is a core dependency.
- Primary teacher: `HuggingFaceTB/SmolLM2-135M`; conditional scale teacher: `HuggingFaceTB/SmolLM2-360M`; `trust_remote_code=false`.
- Scientific execution: PyTorch FP32 on validated MPS or explicitly labeled CPU; numerical references: CPU FP64; deployment comparisons: the same validated MLX runtime.
- Primary context: 512 tokens; reported KL temperature: 1.0; initial head-position chunk: 32; accumulation target: 8192 valid predicted tokens per update.
- Initial complete bank: `K=15`, FFN residual rank `8`, residual scale `1.0`; original depth, attention, norms, tokenizer, RoPE, and embedding/head tying are preserved in the primary mechanism track.
- Initial payload anchor: a validated `K=15`, rank-8, 4-bit, group-64 bank bundle with BF16 residuals; use actual complete file sizes, not a parameter estimate.
- No protected outcomes may influence fitting, search, calibration, tuning, exclusions, or selection; every protected evaluation verifies an immutable freeze.
- Unsupported operations, missing measurements, and infeasible budgets are explicit statuses with reasons; they are never replaced by invented values or silent fallbacks.
- Do not commit raw datasets, downloaded checkpoints, credentials, large generated artifacts, or restricted third-party source code.

## Review Focus

These five easily missed input/failure classes are pinned to concrete task tests below:

1. EOS equals padding, an empty target set, or a ragged final chunk: score only real targets, keep actual denominators, and never divide by zero (Tasks 3, 5, 7).
2. Candidate weights change while the partition is unchanged: invalidate student-state caches and preserve nonzero frozen-suffix input gradients (Tasks 3, 10, 13).
3. Interruption after a merge or protected-data read: restore a coherent checkpoint without resetting spent budget or holdout exposure (Tasks 11, 22, 23).
4. Native serialization/quantization duplicates a shared owner, expands a tied head, or uses a default external corpus: fail before claiming bytes, fidelity, or native execution (Tasks 8, 9, 19).
5. Near-duplicate chains, missing paired rows, and unequal document lengths: preserve split components and refuse biased ratio estimates or selective deletion (Tasks 6, 21, 23).

This is one dependent research system, not independent apps. The phases below have useful standalone outputs. No phase authorizes its successor without the recorded evidence gate.

| Phase | Tasks | Blueprint gate | Independently useful output |
|---|---|---|---|

Task 25 is also executable immediately after **any terminal gate** using only evidence already produced. Tasks whose entry gate is not met stay unchecked and explicitly unexecuted. A diagnostic stop does not require building the compiler just to finish the report.

Follow this cycle per task: write meaningful failing tests, observe the intended failure, implement the named contract, run focused checks, inspect outputs, and commit only its files. Setup/configuration belongs to the first task that uses it. No giant scaffolding commit with placeholder implementations. Use explicit file lists in `git add`; record any method deviation before interpreting results. Update `PROGRESS.md` and `DECISIONS.md` with gate evidence, not unsupported success claims.

Tests use `pytest` markers `cpu`, `mps`, `mlx`, `assets`, `slow`, and `protected`. The default suite is CPU/offline/tiny. Hardware/asset tests are explicit and separately summarized; a skip is never evidence of a passed gate. GPU timing is not an assertion in CPU CI. Integration tests marked `assets` require locally pinned manifests and must never download automatically. Test fixtures use temporary directories and tiny synthetic records; do not include benchmark texts or model weights in Git.

Tests shown below are required behavioral assertions, not complete test implementations. The owning task creates the named fixtures and imports its declared interfaces. Other implementations satisfying the same precise contracts are allowed. CPU FP64 analytic controls can use `atol=1e-12`; accelerator/reference tolerances are measured and saved by Task 2/7, never enlarged to make a regression pass.
