# Confirmation access v1

Implement WP7's missing freeze-verifying issuer and protected-reader branch using owned fixtures only. Existing exploratory purpose/role denials and the nonpublic EvaluationPermit constructor remain. No historical protected data or actual confirmation is authorized by this implementation.

The chosen approach is a closed, versioned metadata freeze plus an exclusive on-disk grant and durable consumption journal. An in-memory-only permit cannot survive interruption; a reusable signed token without consumption state permits adaptive reuse. This local workflow gate verifies frozen files and exposure state; it does not grant platform/data permissions or defend against an operator deliberately deleting all audit state.

Authorization is an explicitly supplied, hash-pinned new-study record binding one freeze, population digest/roles, confirmation purpose, canonical exposure ledger and exclusive permit directory. The freeze binds protocol and analysis files, exact method IDs and artifact-manifest IDs. Artifact completeness/backend qualification remains the bundle/evaluation gate; this reader does not certify model quality. A caller supplies an immutable EvaluationContext matching those exact identities. Only confirm_A/confirm_B are eligible in v1; protected_benchmark remains denied.

Issue without text I/O. Recheck all metadata hashes and the entire manifest before text I/O. Require nonempty population, per-document text hashes and an initially empty existing exposure ledger. Create the grant directory exclusively; failed/incomplete issuance never silently resets. Store grant hash and durable issued state. Reader validates grant/context/authorization/freeze/current files/population, rejects subset or wrong-purpose use and atomically claims both grant journal and exposure ledger before reading. Preserve normal exposure_intent/fingerprint lineage. One attempt consumes the population even after failure/interruption; duplicate/concurrent access and reissue fail closed. Missing/corrupt journal, changed paths, aliases, populated exposure ledger or changed frozen files deny. Materialize before yielding, recheck frozen metadata, record completion or failure with no raw text in grant journals.

Tests cover successful frozen owned access, every binding mismatch, all exploratory callers, interrupted first read, durable order, reused permits, concurrent grants for one population, tampered/deleted records, symlinks and hardlinks. Existing reader behavior remains unchanged when no new confirmation path is requested. Resource bounds: owned CPU fixture work only; focused tests 180s/2GiB, full default CPU suite 1800s/12GiB, no accelerator/model/corpus jobs. Full source/environment/evidence hashes, failures and one fresh whole-feature review precede qualification.

Ruling: proceed inline under the user's explicit end-to-end execution instruction; no additional design approval is needed. No final-data access is made by these tests. A future confirmation driver still requires a prospectively frozen promising claim, justified sample size and actual data permission.
